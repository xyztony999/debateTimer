# PRD — 比赛记录与复盘（迭代包 B）

| 属性 | 值 |
|------|-----|
| 版本 | v1.0 |
| 状态 | 待评审 |
| 所属模块 | S-03 比赛记录管理（S-03-01~04）；关联 C-01（事件来源）与 S-01（模板快照） |

## 1. 背景与目标

比赛结束后，组织方需要复盘：哪个环节超时、双方实际用时多少、整场节奏如何。现状计时数据
随页面刷新即失。目标：以最低干扰（不打断计时）沉淀每场比赛的结构化记录，支持查看与导出。

## 2. 角色与用户故事

| 角色 | 故事 |
|------|------|
| 计时操作员 | 比赛结束（或中途）一键保存比赛记录，失败可重试且不影响比赛 |
| 计时操作员 | 赛后在记录页查看每阶段计划 vs 实际用时和超时次数 |
| 计时操作员 | 把记录导出 CSV 给裁判组 / JSON 存档 |
| 管理员 | 代管查看归属人的比赛记录 |

## 3. 功能范围

### 3.1 做什么

1. **过程采集（FR-B1）**：控制端在计时操作中本地累计：每阶段进入/离开时间、双方运行秒数、
   超时事件（locked）；比赛开始/结束时间
2. **保存提交（FR-B2）**：计时页「保存记录」按钮 + 会话结束自动提交（可关）；内容含模板快照
3. **列表与详情（FR-B3）**：新页面 `/records`：分页列表（时间/模板/队名/阶段数/超时数）；
   详情按阶段展示 计划秒 vs 实际秒（正/反）、超时标记、宽限用量
4. **导出（FR-B4）**：详情页导出 CSV / JSON
5. **删除（FR-B5）**：确认后物理删除

### 3.2 不做什么

- 不做记录编辑/批注（只读 + 删除，B-C3）
- 不做跨记录统计报表/图表（后续迭代）
- 不做匿名独立模式记录（B-C7）
- 不做服务端实时写入/高频心跳落库（一次性提交，B-C1）
- 不做记录分享（复盘是归属人内部动作）

## 4. 功能需求详述

### FR-B1 过程采集（控制端本地）

- 采集时机：阶段切换（进入/离开）、启停（累计运行秒）、locked 事件（超时+1，按方）
- 每阶段条目：`{stageId, label(按当前语言快照), mode, plannedSeconds, graceSeconds,
  actualAffSeconds, actualNegSeconds, overrunAff, overrunNeg, enteredAt, exitedAt}`
- 单计时记入 actualAffSeconds；自由辩论双方分计
- 比赛元：`configName, teamNames 快照, startedAt(首个阶段进入), endedAt(保存时)`

### FR-B2 保存提交

- 触发：手动按钮（任意时刻，提交「截至当前」的记录）或控制会话结束自动提交（默认开）
- `POST /api/match-logs`（owner + CSRF）；成功 toast；失败本地暂存（内存 + 提示重试，B-C6）
- 重复提交：每次保存生成**新记录**（同一场比赛可存多份快照式记录，以 savedAt 区分）——
  简单且符合「快照」语义

### FR-B3 列表与详情

- `GET /api/match-logs?limit&before`（owner；admin 可带 ownerId 代查）→ 降序列表
- `GET /api/match-logs/:id` → 详情（全部字段）
- 页面：`/records`（列表）+ `/records/:id`（详情）；列表行点击进详情

### FR-B4 导出

- 详情页导出 CSV / JSON；**服务端仅提供 JSON 附件端点**（`GET /api/match-logs/:id/export?format=json`），
  CSV 由前端基于详情数据在浏览器内生成（Blob 下载，含 BOM，单元格做公式注入防护与转义）
- CSV 列：序号/阶段/模式/计划秒/实用秒(正)/实用秒(反)/超时(正)/超时(反)/进入时间/离开时间
- 文件名：`match-{YYYYMMDD-HHmm}-{configName}.csv|json`

### FR-B5 删除

- `DELETE /api/match-logs/:id`（owner）；前端二次确认

## 5. 角色权限

| 操作 | 操作员 | 观众 | 管理员 |
|------|--------|------|--------|
| 保存/删除记录 | ✓（本人） | ✗ | 删除仅本人；查看可代管 |
| 查看/导出 | ✓（本人） | ✗ | ✓（带 ownerId） |

## 6. 领域对象与数据

**聚合根 MatchRecord（新集合 `match_logs`）**

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | ObjectId | |
| ownerId | ObjectId | 归属人 |
| configName | string | 模板名快照 |
| teamNames | {aff?,neg?} | 队名快照 |
| startedAt / endedAt / savedAt | long | 比赛起止 / 提交时间 |
| stages | array | 阶段条目（FR-B1 结构 + planned/grace 快照） |
| summary | {totalPlannedSeconds, totalActualSeconds, overrunCount} | 派生汇总（提交时计算存储） |

关系：MatchRecord N:1 配置文档（仅存 configName 快照，不存 ObjectId 引用——模板可删，记录独立存续）。

## 7. 状态流转

记录无状态机（append-only 存档；生命周期 = 创建 → 删除）。

## 8. 业务规则

| # | 规则 |
|---|------|
| BB-1 | 超时判定：某方 locked（主时间+宽限尽）计一次；重置后再次 locked 再计 |
| BB-2 | 阶段实际用时 = 该阶段内该方 running 累计秒数（宽限秒计入实际用时） |
| BB-3 | stages ≤ 64 条；单条记录 ≤ 64KB；超出截断并标记 |
| BB-4 | 记录创建后服务端不改写（导出为只读投影） |
| BB-5 | 列表默认 20 条/页，最多返回 100 条/请求 |
| BB-6 | configName 以快照存储，不校验模板存在性 |

## 9. 非功能性

| # | 要求 |
|---|------|
| BN-1 | 采集为纯前端本地行为，零额外网络请求；提交单次 POST ≤64KB |
| BN-2 | 单归属人记录无硬上限（MongoDB）；列表游标分页 |
| BN-3 | 导出同步生成（无后台任务），CSV 带 BOM（Excel 中文兼容） |

## 10. 异常场景

| 场景 | 处理 |
|------|------|
| 保存时断网 | 本地暂存 + 重试提示（B-C6） |
| 比赛中途刷新页面 | 采集数据丢失（本地 state）——记录仅覆盖刷新后的部分；详情按实际数据呈现 |
| 模板赛后被删/改名 | 记录不受影响（快照） |
| 会话结束自动保存时恰好失败 | 同断网处理，手动补存 |

## 11. 验收标准

1. 打完整场比赛（含宽限/自由辩论），保存后详情页每阶段的计划/实际/超时与人工观察一致
2. CSV 导出在 Excel 打开中文不乱码；JSON 与详情一致
3. 会话结束自动生成记录；手动保存可多次生成多份记录
4. 非本人无法查看/删除（403/404）；admin 可带 ownerId 查看
5. 回归：无记录操作时计时行为与线上完全一致
6. 门禁全绿
