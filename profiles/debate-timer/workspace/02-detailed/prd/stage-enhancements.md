## 1. 背景与目标

### 1.1 解决什么问题

- 现状时间耗尽即长鸣锁定，辩手常被「硬切」——赛制惯例允许数秒收尾（宽限），且需要区分
  「时间到」与「必须停」两段提示
- 提示音全局固定一种、音量不可调，现场设备差异大（投影音箱 vs 手机）
- 正反方只有「正方/反方」通用称谓，正式比赛需要队名上屏
- 主席需手动点击每个阶段切换，流程性环节希望自动推进减少操作

### 1.2 为谁提供价值

计时操作员（更少误操作、更清晰的收尾信号）、观众/辩手（队名与明确的收尾节奏）、
赛事组织（赛制表达力：宽限与自动推进进入模板配置）。

### 1.3 业务目标

1. 时间到不再硬切：宽限内可收尾，两段铃声语义明确
2. 主席每阶段少点 1–2 次（自动推进），提示音适配现场设备
3. 模板可完整表达一套赛制（模式/宽限/推进/队名）

## 2. 角色与用户故事

| 角色 | 用户故事 |
|------|---------|
| 计时操作员 | 时间到时我想先给短提示，给辩手几秒收尾，宽限尽再长鸣强制停止 |
| 计时操作员 | 我想给 30 秒提醒/时间到/必须停各配不同铃声和音量，并先试听 |
| 计时操作员 | 我想在模板里填两队队名，让大屏直接显示 |
| 计时操作员 | 流程性阶段结束后我想让计时器自动进入下一阶段，误触时可取消 |
| 观众 | 大屏要显示队名；时间到和必须停的提示要能看清听清 |

## 3. 功能范围

### 3.1 做什么

1. **超时宽限（FR-A1）**：阶段级宽限秒数（默认 0）；两段铃声与相位渲染；随快照同步大屏
2. **提示音自定义（FR-A2）**：按告警节点（30 秒/时间到/必须停）选铃声方案 + 音量 + 试听；
   浏览器本地偏好；控制端与显示端各自配置；大屏页提供本地入口
3. **队名上屏（FR-A3）**：模板级队名；计时页双计/自由辩论布局与大屏显示
4. **自动阶段推进（FR-A4）**：阶段级标志；结束后 3 秒推进，手动取消，末阶段不推进

### 3.2 不做什么

- 辩手名逐阶段配置（预置阶段名已含辩手信息，双计时不区分辩手——A-C4）
- 宽限期间继续正常发言计时的「软限时」赛制变体（宽限仅为收尾倒计时）
- 铃声文件上传（仅内置铃声方案，避免存储与审核问题）
- 提示音偏好同步到账户/服务端（保持本地偏好，同主题/语言定位）
- 每阶段独立铃声节点（节点=告警类型，非阶段维度）

## 4. 功能需求详述

### FR-A1 超时宽限（C-01-06）

- 配置：`stageGrace[stageId]` 整数秒，0–300，默认 0（关闭）；设置页阶段编辑提供输入
- 行为（单/双/自由辩论通用）：
  - 主时间耗尽 → 播放「时间到」短铃 → 时间显示切换为宽限倒计时（橙色闪烁）→ 计时相位 `grace`
  - 宽限耗尽 → 播放「必须停」长鸣 → 持续红色闪烁锁定 → 相位 `locked`
  - 宽限=0 时维持现状（直接长鸣锁定）
  - 重置/阶段切换清除宽限相位
- 双计时：任一方进入宽限即该方进入宽限渲染；自由辩论双方归零后按各自宽限锁定
- 快照扩展：`phaseAff/phaseNeg`（running/grace/locked，缺省 running）、`graceAffMs/graceNegMs`（各方宽限剩余；设计修订：按方并行以表达双方各自相位）
- 大屏跟随：经快照同步相位与宽限剩余；两段铃声按显示端本地偏好发声

### FR-A2 提示音自定义（P-02-03）

- 偏好结构：`{ warn30: {sound, volume}, timeUp: {...}, mustStop: {...} }`，localStorage 持久化
- 铃声方案：内置 ≥2 种/节点（含新增「时间到」短铃资产；「必须停」复用既有长鸣）
- 设置页「提示音」卡片：三节点各一行（方案下拉 + 音量滑杆 + 试听按钮）；恢复默认按钮
- 大屏页：导航区提供提示音入口（弹层，匿名可用，本地生效）
- 生效范围：控制端与显示端各自读取本地偏好（同一物理设备配置一次即可）

### FR-A3 队名上屏（S-01-06）

- 配置：`teamNames: { aff: string, neg: string }`，随模板保存；空值回退「正方/反方」
- 渲染：双计时/自由辩论布局中双方标题由队名替代（正/反标记保留为徽标）；大屏跟随与独立模式一致
- 快照：队名经配置文档流到达显示端（`toDisplayResponse` 含 `teamNames`），不入快照

### FR-A4 自动阶段推进（C-01-07）

- 配置：`stageAutoAdvance[stageId]` 布尔，默认 false；设置页阶段编辑提供开关
- 行为：当前阶段**彻底结束**（单：锁定；双/自由：双方锁定；含宽限耗尽）且标志开启 →
  显示「3 秒后进入下一阶段」倒计时 → 到时执行阶段切换（等价 C-01-04 原语）
- 取消：倒计时期间任何手动操作（按钮、快捷键、下拉切换）立即取消本次推进
- 边界：最后一个阶段不推进；跟随模式下大屏只呈现、推进由控制端快照驱动

## 7. 状态流转（增量）

计时相位（每方/单方，前端本地+快照）：

```
running --主时间归零(有宽限)--> grace --宽限归零--> locked
running --主时间归零(无宽限)--> locked
任意相位 --重置/切阶段--> running(新阶段)
```

自动推进（前端本地）：

```
idle --阶段彻底结束且标志开--> advancing(3s倒计时) --到时--> 切换+idle
advancing --任何手动操作--> idle(取消)
```

## 8. 业务规则

| # | 规则 |
|---|------|
| AB-1 | 宽限秒数 0–300 整数，默认 0；负数/非整数服务端拒绝（400） |
| AB-2 | 宽限相位期间不产生「正常发言计时」语义：时间显示为宽限倒计时，不回补主时间 |
| AB-3 | 两段铃声语义固定：「时间到」进入宽限时、「必须停」宽限耗尽时；铃声方案可换、语义不可换 |
| AB-4 | 提示音偏好仅存本地，不上传；设备间不同步 |
| AB-5 | 队名 ≤ 20 字符；空值回退默认称谓；不入快照（经配置流分发） |
| AB-6 | 自动推进仅在阶段彻底结束后触发；期间任何手动输入取消；末阶段不推进 |
| AB-7 | 旧客户端读取新配置：忽略未知字段不崩溃；旧显示端收到含新字段的快照同样忽略 |

## 9. 非功能性要求

| # | 要求 |
|---|------|
| AN-1 | 宽限/推进为纯前端行为 + 快照扩展，服务端仅校验配置字段，无新端点 |
| AN-2 | 铃声试听即点即响（预加载，复用现有 Audio 预热机制） |
| AN-3 | 快照新增字段 ≤ 64B，心跳与广播开销不变 |

## 10. 异常场景

| 场景 | 处理 |
|------|------|
| 宽限期间断线重连 | 快照携带 timerPhase/graceMs，大屏恢复即对齐相位 |
| 自动推进倒计时中会话结束 | 推进状态为控制端本地行为，随会话结束消失；大屏回退独立模式 |
| 提示音资产加载失败 | 回退默认提示音路径，不阻塞计时（沿用现有静默容错） |
| 旧配置无新字段 | 全部缺省：宽限 0、推进关、队名默认 |

## 11. 验收标准

1. 宽限 30 秒的阶段：主时间到 → 短铃+橙闪宽限倒计时 → 宽限尽 → 长鸣+红闪锁定；大屏同步同相位
2. 提示音设置：三节点分别换铃声/调音量/试听即时生效；刷新后保留
3. 队名保存后，控制端与大屏双计/自由辩论布局显示队名；空值显示默认
4. 开启自动推进的阶段结束后 3 秒自动切换；倒计时内按任意键取消；末阶段不推进
5. 旧配置（无新字段）行为与线上一致（回归）；含非法宽限值保存返回 400
6. 全部门禁（lint/test/build）通过
