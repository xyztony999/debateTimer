## 0.1 业务概念解析

| 维度 | 提取结果 |
|------|---------|
| 业务术语 | 控制端（计时操作员所用设备）、显示端/大屏（投影只读屏）、控制会话、计时状态快照、跟随模式、独立模式、自由辩论（free_debate，预置阶段）、自动切换、阵营（正方/反方）、shareToken |
| 业务流程 | 开启分享 → 控制端发起控制会话 → 计时操作 → 状态快照上报 → 服务端中转 → 大屏跟随渲染 → 断线重连恢复 → 会话结束 |
| 业务角色 | 计时操作员（主席/计时员，模板 owner，认证用户）、观众（大屏匿名访问者）、管理员 |
| 业务规则 | 仅 owner 可上报状态；显示端在会话活跃期只读；快照以 seq 单调递增；自由辩论中停止一方自动启动对方；一方时间耗尽自动切换，双方耗尽则阶段结束 |
| 业务数据 | 计时状态快照：会话标识、当前阶段、计时模式、正/反方剩余毫秒、运行标志、活跃阵营、服务器时间戳、序号 |

## 0.4 逐项澄清（自治默认决策，D 复核点）

| # | 澄清点 | 决策 | 理由 |
|---|--------|------|------|
| C1 | 显示端语义 | 会话活跃 → 只读跟随；无会话 → 保持现状（匿名独立可操作），向后兼容 | 不破坏既有使用方式 |
| C2 | 状态权威方 | 控制端计算时间，服务端仅内存缓存最新快照并中转，不做服务端 tick | 避免服务端定时任务与持久化压力；SSE hub 现有形态一致 |
| C3 | 时间校准 | 快照携带 serverTimestamp；显示端计算钟偏并本地插值倒计时 | 亚秒级跟随，不依赖连续推送 |
| C4 | 推送策略 | 状态变化即推 + 周期心跳（2s）冗余；SSE 重连后先 GET 全量再续订 | 丢包可容忍（插值兜底），重连必须精确 |
| C5 | 多控制端冲突 | 不做互斥；快照 seq 单调递增，显示端取最新（last-writer-wins） | 现场单人操作为主，简化实现 |
| C6 | 自由辩论语义 | `timerSettings` 枚举扩展 `'free'`；显式停止一方 → 自动启动对方；一方到时 → 自动切换；双方到时 → 阶段结束；支持手动改判（Reset 恢复常规操作） | 用户批准的描述："一方暂停（或按键）自动切到另一方计时" |
| C7 | 权限 | 状态上报/会话管理仅限该配置 owner（cookie 会话 + CSRF，沿用现有机制）；显示端读取匿名（shareToken） | 与现有 share/display 权限模型一致 |
| C8 | 持久化 | 控制会话与快照不落库（服务端内存态），服务重启即失效，显示端回退独立模式 | 比赛现场时长有限，可接受；降低复杂度（N 层决策） |
| C9 | 兼容性 | 旧客户端不识别 `'free'` 时按 `'double'` 降级处理 | 平滑升级 |
