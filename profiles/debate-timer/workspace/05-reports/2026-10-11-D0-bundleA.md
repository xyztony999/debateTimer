# D0 需求澄清报告 — 迭代包 A：赛制增强（宽限/提示音/队名/自动推进）

| 属性 | 值 |
|------|-----|
| 日期 | 2026-10-11 |
| 输入 | 超时宽限、提示音自定义、队名/辩手名上屏、阶段结束自动进入下一阶段 |
| 运行模式 | 增量（架构文档 v1.0 已存在，D1 走变更管理） |

## 0.1 业务概念解析

| 维度 | 提取结果 |
|------|---------|
| 术语 | 宽限（grace）、时间到 vs 必须停（两段铃声）、告警节点（30秒/时间到/必须停）、铃声方案与音量、试听、队名（正方/反方显示名）、自动阶段推进、推进取消 |
| 角色 | 计时操作员（配置与操作）、观众（大屏观看，感知铃声/队名/推进） |
| 流程 | 阶段时间耗尽 →（有宽限）进入宽限倒计时（短铃+闪烁）→ 宽限耗尽（长鸣+锁定）→（有自动推进）3 秒后切下一阶段（可取消） |
| 规则 | 宽限为阶段级属性默认 0；提示音偏好为浏览器本地偏好；队名随模板存储；自动推进期间任何手动操作取消推进；双方/单方计时均适用宽限语义 |
| 数据 | `stageGrace`（秒）、`stageAutoAdvance`（bool）、`teamNames{aff,neg}`（模板级）、铃声偏好（localStorage）、快照扩展字段 |

## 0.2 匹配已有架构（v1.0）

| 需求概念 | 匹配 | 差异 |
|---------|------|------|
| 超时宽限 | 部分匹配 C-01-05 计时提示告警 / C-01-01/02 计时控制 | 新增「时间到后继续收尾」的计时相位与两段铃声；配置 schema 新字段 |
| 提示音自定义 | 部分匹配 C-01-05（固定一种提示音） | 按节点选铃声/音量/试听；浏览器本地偏好（同 P-02 主题基座定位） |
| 队名上屏 | 无匹配 | 模板级新字段；计时页/大屏/快照渲染 |
| 自动推进 | 部分匹配 C-01-04 比赛阶段切换（手动） | 新增自动触发路径与取消语义 |

## 0.3 需求类型

全部为**增强**（既有模块扩展）→ D1 场景二变更管理，入口 = BA（新增/扩展 L4）。

## 0.4 决策（A-C1~C6，见对话记录归纳）

| # | 决策 |
|---|------|
| A-C1 | 宽限=阶段级 `stageGrace` 秒数，默认 0（关闭） |
| A-C2 | 两段铃声：时间到=新单响短铃+闪烁；必须停=既有长鸣+持续红闪；铃声资产随 A2 可换 |
| A-C3 | 提示音偏好按告警节点配置（铃声/音量/试听），localStorage 存储，双端各自生效 |
| A-C4 | 队名=模板级 `teamNames`；辩手名不做（阶段名已承载辩手信息，双计时不区分） |
| A-C5 | 自动推进=阶段级标志；阶段彻底结束（含宽限）后 3s 切换，手动操作即取消；末阶段不推进 |
| A-C6 | 快照增加可选字段（`graceMs`/`timerPhase`），旧显示端忽略不崩溃 |
