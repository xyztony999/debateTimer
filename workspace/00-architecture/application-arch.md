## 第一部分：文档概述

本文档将《业务架构》（business-arch.md v1.0）的 6 个 L3 归类映射为 DDD 四层应用域，标注功能模块的用户类型与调用关系，并补充 BA 范围外的系统级功能（权限治理、系统配置、平台支撑），作为功能清单与 API 设计的输入。

### 1.1 背景与目标

系统已上线运行（前端 React19+Vite+MUI、后端 Express+MongoDB）。应用架构以业务架构为唯一上游：比赛计时与大屏同步归核心业务域（有状态机与聚合根），准入/模板/广场/记录归支撑业务域（含业务规则），系统级治理归基础数据域，纯技术机制归平台支撑域。目标是让后续 D2 领域建模与 D3 API 设计能按分层决定投入深度。

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

四个应用域中，核心业务域承载现场比赛的执行闭环（计时 + 协同呈现），是系统价值所在；支撑业务域提供准入、赛制、内容分发与归档四类业务支撑；基础数据域与平台支撑域承接 BA 未涵盖的系统级功能（治理、配置与纯技术机制）。核心域的状态（计时、会话）由支撑域供给输入（模板、账号），并向支撑域沉淀产出（记录）。

### 应用域分层

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | C-01 比赛计时、C-02 大屏同步与远程控制 |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | S-01 账号与准入、S-02 赛制模板管理、S-03 模板广场、S-04 比赛记录与复盘 |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | D-01 权限与用户治理、D-02 系统配置 |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | P-01 实时通信通道、P-02 接口防护、P-03 离线应用壳 |
