## 0. 怎么读这份文档

本项目的线上服务已经有真实第三方用户。本轮设计自始至终受两条约束：**任何设计都不得包含对线上数据的破坏性操作；涉及数据变更的必须可回滚**（§9.2）。

## 1. 现状基线与范围

### 1.1 现状事实

以下事实由主会话核实后提供，本轮设计以此为基线。

| 方面 | 现状 |
|------|------|
| 用户 | 线上 9 个普通账号（2026-11-01 至 11-15 陆续注册）与 1 个管理员 |
| 登录 | 仅用户名加口令（bcrypt），会话 Cookie；没有任何二次验证 |
| 隐私告知 | 没有隐私说明、同意记录或条款 |
| 应用采集的数据 | 服务端不存 IP 与 User-Agent；会话记录只有令牌散列、账号 id、创建时间、过期时间 |
| 用户的数据权利 | 没有自助导出或删除入口；只有管理员可删除账号（`DELETE /api/admin/users/:id`） |
| 注册开关 | 管理员后台设置（app_settings 单文档），优先于环境变量 |
| 审计 | 服务端没有审计日志；用户文档只有创建时间；后台用户表不显示注册时间；注册开关的最后修改人与时间接口有返回但界面不显示 |
| 反向代理 | `server/index.js` 设 `trust proxy = 1`；已有内存限流（`server/lib/rateLimits.js`） |
| 部署 | 前端 GitHub Pages；API 与 MongoDB 在宝塔服务器；主域 `debatetimer.tonyxyz.com` 经 Cloudflare 代理（橙云），`api.debatetimer.tonyxyz.com` 仅 DNS 解析（灰云，2026-11-24 多次解析核实） |
| 最近两次提交 | `7c94678` 注册页文案修复（`registerCopyKeys`）；`aa72c9f` 官网字体非阻塞加载与文案。应用入口页 `index.html` 的字体仍是阻塞式加载，本轮改为非阻塞 |

### 1.2 范围

**本轮做**：

- 两步验证（TOTP）：管理员强制，普通用户自愿。
- 审计日志：完整 IP，留存 184 天，到期自动删除（2026-11-24 用户裁决，由 180 天改定）。
- 隐私告知：注册页展示隐私说明并必须同意；已有用户再次使用时展示并要求确认。
- 应用入口页网页字体非阻塞加载（用户追加）。

**本轮不做**：用户自助导出或删除数据；§10 列出的各项服务级事项。

### 1.3 对线上数据的约束

| 约束 | 本轮如何满足 |
|------|-------------|
| 不破坏线上数据 | 部署不改写任何既有文档：新字段按需追加（缺省即「未绑定」「未确认」），新集合 `audit_logs` 为空集合起步。没有任何迁移脚本 |
| 可回滚 | 回滚即回退代码并重启；遗留的新字段与新集合对旧代码无影响（§9.5） |
| 唯一会批量改动既有数据的操作 | 账号删除时的审计清洗。它只在管理员主动删除账号时发生，且清洗的是本轮新建的 `audit_logs`，不触碰其他集合 |

### 2.2 设计决策（本轮设计方作出）

| 编号 | 决策 | 理由 | 主要落点 |
|------|------|------|---------|
| D48 | 审计日志独立为平台支撑域新模块 P-04；事件类型白名单；只增写入 | 审计是零业务语义的可复用机制；白名单从结构上限定记录范围 | AA v1.2 §2.4.4；P-04 PRD §3.3、§5.2 |
| D49 | 审计事件采用「操作者、所涉账号、专属字段」三元模型，专属字段按事件类型白名单 | 用户名读出时解析，不冗余存储；变更前后值只出现在三种事件 | P-04 PRD §3.3、§7 |
| D50 | 「先告知后收集」分三档：注册须勾选同意；存量用户确认前不记 IP；匿名失败尝试以登录页表单前的告知覆盖 | 无法对匿名请求逐人取得同意；对已识别的账号则可以也应当等其确认 | P-04 PRD §5.1；S-01 PRD §5.6；本文 §5 |
| D51 | 登录后门控按请求实时派生，由服务端中间件强制；存量会话不销毁 | 不改会话记录、不强制下线即可让已登录用户进入确认与绑定；直接调接口也绕不过去 | S-01 API §3.5 |
| D52 | 口令通过后签发预登录凭据（5 分钟、单次、只存散列、进程内存），不是会话 | 二次验证完成前不应存在会话 | S-01 API §4.3、§4.4「TOTP-VERIFY」 |
| D53 | TOTP 采用 RFC 6238 标准参数（30 秒、6 位、SHA-1），允许前后各一步，已用时间步不再接受，判定与记录为一次原子更新 | 兼容主流验证器；防重放 | S-01 API §4.1（领域服务表 `totp` 行） |
| D54 | 密钥以 AES-256-GCM 加密，主密钥取自环境变量 `TOTP_SECRET_KEY`；未配置时两步验证停用并告警，绝不退回明文 | 用户硬要求；停用而不是拒绝启动，是为了不让一次配置遗漏把整站或管理员锁死 | S-01 API §3.4、§4.4「TOTP-SETUP」；本文 §8.1 |
| D55 | 恢复码 10 个，每个 10 字符，只存 SHA-256 散列，一次性 | 验证器丢失后的登录通道；高熵随机串用快速散列即可 | S-01 PRD §5.5 |
| D56 | 二次验证按账号限流：15 分钟 5 次失败，动态口令、恢复码与绑定确认共用计数 | 分开计数，恢复码或绑定确认就成为并行的猜测通道 | S-01 API §4.4；EP-PROTECT-03 |
| D57 | 管理两步验证需要密码证明（10 分钟内登录过，或输入当前口令）；管理员不可关闭；管理员可重置他人；服务器脚本作为唯一管理员的解围通道 | 防止别人借用未退出的电脑绑定自己的验证器或关掉两步验证；线上只有一名管理员，必须有界面之外的解围办法 | S-01 PRD §5.5；D-01 PRD FR-6 |
| D58 | 审计读取：管理员全量加筛选分页；本人只看登录类事件，失败事件的 IP 脱敏 | 失败请求可能来自持有口令的第三方，其完整 IP 不应给另一名用户看 | P-04 PRD §5.5 |
| D59 | 删除账号时先清洗审计日志再删账号：自身活动事件删除，其余引用匿名化，保留删除事件 | 先删后洗一旦失败，带标识的日志永久残留且无法重试 | P-04 PRD §5.4 |
| D60 | 审计日志纳入备份，恢复后对已不存在的账号重放清洗 | 数据库损坏时审计记录不丢；恢复不让已清洗的标识复活 | P-04 PRD §5.6 |
| D61 | 隐私说明以服务端内容模块发布，版本为常量；同意记录为「版本 + 时间」；版本变更后全员重新确认 | 说明版本与同意对象一一对应 | S-01 API §4.4「PRIVACY-NOTICE」 |
| D62 | 存量数据零迁移：部署不改写既有文档 | 对线上数据的不破坏约束 | 本文 §9.2 |
| D63 | 注册同意随注册请求校验；管理端开的账号首次登录走存量确认流程 | 同意必须发生在建号之前；管理端开号没有经过注册页 | S-01 API §4.4「REGISTER」；D-01 PRD FR-2 |
| D64 | 审计写入失败则当前请求失败，不静默放行 | 留痕是被审计动作的一部分 | P-04 PRD §5.2 |
| D65 | 隐私说明正文与事实以代码常量维护，不走环境变量注入 | 说明文本与版本号一并受版本控制与审阅；运行时注入会让已发布的文本与审定过的文本不一致 | S-01 API §4.4「PRIVACY-NOTICE」 |

### 2.3 其中属于「设计方默认取舍」的项

D48–D65 中有 8 项是用户裁定的自然延伸之外、由设计方选定的做法。它们不与任何裁定冲突，但会改变产品行为，集中列在 §11.1。**用户已于 2026-11-24 裁决全部按本设计执行**，八项现均已裁定。

## 5. 「先告知后收集」机制

### 5.1 三类情境

| 情境 | 能否逐人取得同意 | 做法 | IP 的处理 |
|------|-----------------|------|----------|
| 新用户注册 | 能 | 注册页必须勾选同意；说明全文加载成功前不能勾选 | 同意与建号在同一请求内，审计事件记 IP |
| 已有用户 | 能，但要等到其下次使用 | 登录后先进入确认页；确认之前其他接口被拒绝 | **确认之前不记**；确认之后记 |
| 未登录的失败尝试（账号不存在或口令错误） | 不能 | 登录页在表单之前展示隐私说明入口与提示行 | 记 |

### 5.2 时间线

```
访客打开登录页
  └─ 表单之前：隐私说明入口 +「记录登录尝试来源 IP」提示        ← 对匿名尝试的告知
提交登录
  ├─ 失败 ───────────────→ login_failed（记 IP）
  └─ 成功
       ├─ 尚未确认当前版本说明 → login_succeeded（不记 IP）
       │        └─ 确认页 → privacy_consented（记 IP：同意已在本请求内发生）
       │                  └─ 之后的事件均记 IP
       └─ 已确认 ───────────→ login_succeeded（记 IP）

注册：说明全文已加载 → 勾选同意 → REGISTER{agree, privacyVersion} → registered（记 IP）
```

### 5.3 一处解读需要知悉

「未登录的失败尝试」是否包括「尝试登录一个尚未确认说明的存量账号」，用户裁定没有明说。本设计按「包括」处理并记录 IP：此时操作者未经身份验证，事件归属于发起请求的一方；而且这类长期不登录的账号（线上现有 9 个普通账号在各自下次访问前都属于此类）恰恰是口令泄露后最容易被尝试的对象，不记 IP 会让它们在这段时间里无从排查。若希望从严，改动只在 `ipFor()` 一处（§11.1 Q3）。

```

#   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
# 未配置时两步验证停用（不会退回明文存储）。请离线备份该值：丢失后已绑定的账号只能逐一重置。
# TOTP_SECRET_KEY=

# 两步验证尝试限流（每账号；动态口令与恢复码共用计数；内存态，重启清零）
# TOTP_ATTEMPT_RATE_WINDOW_MS=900000
# TOTP_ATTEMPT_RATE_MAX=5

# 隐私说明读取接口限流（每 IP）
# PRIVACY_RATE_WINDOW_MS=60000
# PRIVACY_RATE_MAX=60
```

### 8.2 主密钥的生成与保管

- 生成：在服务器上执行上面的 `node -e` 命令，把输出写入 `server/.env` 的 `TOTP_SECRET_KEY`。
- **丢失**：已绑定账号的密钥无法解密，这些账号无法通过二次验证，只能由管理员重置或运行服务器脚本重置。因此生成后立即离线备份一份。
- **泄露**：拿到主密钥的人还需要拿到数据库才能解密。但一旦发生，没有现成的轮换工具（§11.2 G5），需要另行编写迁移脚本。
- 存放：只在 `server/.env`。不进 git，不进备份，不写进文档或工单。
- 长度校验：base64 解码后必须恰好 32 字节，否则按「未配置」处理。

### 8.3 社区自部署

自部署者需要自行生成 `TOTP_SECRET_KEY`，并以自己的主体信息改写隐私说明内容模块（`server/lib/privacyNotices.js`）与版本号。默认内容描述的是本项目线上服务的运营者与托管安排。

### 9.3 IP 真实性：前置条件与确认方法

审计日志记到的 IP 取自 `req.ip`。它是否为真实客户端地址，取决于请求到达 Node 之前经过了几跳代理。

**已核实的事实（主会话，2026-11-24）**：

- `api.debatetimer.tonyxyz.com` 目前是灰云，当天多次解析均得到宝塔服务器直连 IP。
- 仓库内的 Nginx 模板 `deploy/baota/nginx/api.snippet.conf` 设置了 `X-Real-IP $remote_addr` 与 `X-Forwarded-For $proxy_add_x_forwarded_for`。
- `server/index.js` 设 `trust proxy = 1`。

按这个组合，Express 取到的是 Nginx 看到的对端地址，也就是真实客户端；客户端自己伪造的 `X-Forwarded-For` 会排在更前面的一跳，不被采信。

**两点局限（如实说明）**：

1. 主会话没有服务器权限，线上 Nginx 是否与模板一致没有核实。
2. 主域 `debatetimer.tonyxyz.com` 是橙云代理。如果将来 api 记录也被改成橙云，而 Nginx 没有配置 Cloudflare 的 realip，那么记到的会是 Cloudflare 的边缘地址，既有的按 IP 限流也会被合并成一个大桶。

**因此写成上线前置条件**：api 域名必须保持灰云，或配置 Cloudflare realip。二者之一不成立时，审计日志里的 IP 与按 IP 的限流都不可信。

**负责人可自行执行的确认方法**：

| 方法 | 做法 | 期望结果 |
|------|------|---------|
| DNS | `nslookup api.debatetimer.tonyxyz.com` | 解析结果不在 Cloudflare 的地址段内 |
| 服务器配置 | 在宝塔中打开 api 站点的 Nginx 配置，找到反代到 `127.0.0.1:3001` 的 `location` | 含 `X-Real-IP $remote_addr` 与 `X-Forwarded-For $proxy_add_x_forwarded_for` |
| 访问日志 | 查看该站点的访问日志首列 | 是分散的客户端公网地址，不是同一个地址或 Cloudflare 地址段 |
| 行为验证一 | 上线后管理员登录一次，到审计日志中查看刚才那条事件的 IP | 等于本机当时的公网 IP |
| 行为验证二 | 从本机执行：`curl -H "X-Forwarded-For: 1.2.3.4" -H "Content-Type: application/json" -d '{"username":"nosuch_user_zz","password":"x"}' https://api.debatetimer.tonyxyz.com/api/auth/login` | 审计日志新增的 `login_failed` 事件中，IP 是本机真实公网 IP，不是 `1.2.3.4` |

后两条在上线后执行；如果 IP 不是真实来源，先修代理配置，再把日志里的 IP 当作依据。

| 1111111111 | 37037037 | 14050471 | 050471 |
| 1234567890 | 41152263 | 89005924 | 005924 |
| 2000000000 | 66666666 | 69279037 | 279037 |
| 20000000000 | 666666666 | 65353130 | 353130 |

上表已在本机用 Node 内置的 `crypto`（Node v22.22.3）按标准算法复算核对：HMAC-SHA1、8 字节大端计数器、动态截断取低 31 位、对 10 的 8 次方取模。同一段实现也复现了 RFC 4226 附录 D 的 10 个向量。6 位口令一列**保留前导零**（如 `081804`、`005924`），测试断言须按字符串比较。代码阶段写测试时如需引用 RFC 原文，可再对照一次。

## 11. 待决事项与风险

### 11.1 默认取舍（2026-11-24 用户已全部确认）

以下 8 项由设计方选定，不与任何裁定冲突，但会改变产品行为。**用户已于 2026-11-24 裁决：八项全部按「本设计」执行，均已裁定**。下表保留作为决策记录。

| # | 取舍点 | 本设计 | 备选 | 设计方建议 |
|---|--------|--------|------|-----------|
| Q1 | 管理两步验证是否需要密码证明；是否提供管理员重置与服务器脚本 | 需要（10 分钟内登录过或输入口令）；提供重置与脚本 | 只要登录就能开启或关闭；不提供重置 | 按本设计。否则借用未退出电脑的人可以给账号绑上自己的验证器；唯一管理员丢失验证器时没有任何解围办法 |
| Q2 | 服务器未配置 `TOTP_SECRET_KEY` 时 | 两步验证停用并告警，管理员强制绑定暂不生效 | 服务启动即拒绝 | 按本设计。备选更严，但一次配置遗漏会让整站不可用 |
| Q3 | 匿名登录失败，被尝试的是一个尚未确认说明的存量账号 | 记录 IP | 不记录 IP | 按本设计，理由见 §5.3 |
| Q4 | 审计日志是否纳入备份 | 纳入，恢复后重放清洗 | 不纳入（与会话一样视为易失数据） | 按本设计。备选的留存边界更干净，但数据库损坏时审计记录全丢 |
| Q5 | 上线时是否让已登录用户重新登录 | 不销毁存量会话 | 销毁全部会话 | 按本设计。门控对存量会话同样生效，不需要强制下线 |
| Q6 | 最低集合之外增补的 4 种事件 | 保留 | 删除 | 保留。它们覆盖的都是提权或不可恢复的操作 |
| Q7 | 隐私说明文案的维护方式 | 代码常量 | 环境变量注入 | 按本设计（D65） |
| Q8 | 「我的登录记录」里失败尝试的 IP | 脱敏显示 | 不显示；或显示完整 IP | 脱敏。发起请求的可能是第三方 |
