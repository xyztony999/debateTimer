## 第一部分：PRD 正文

### 1. 业务背景与目标（G1）

系统为辩论社提供赛制模板、比赛计时与复盘记录能力，这些资产按账号归属隔离（模板、比赛记录均以 ownerId 存储）。S-01 解决「谁能进入系统」：

- 访客可自行注册账号，无需管理员人工开通；
- 已注册用户以用户名/口令登录，登录态跨页面保持；
- 管理员可开放/关闭公开注册，防止滥用。

服务对象：访客（注册/登录）、注册用户与管理员（登录态保持）、管理员（准入开关）。

### 2. 角色与职责（G3）

| 角色 | 职责与权限 | 实现依据 |
|------|-----------|---------|
| 访客 | 注册账号、登录；注册关闭时收到「联系管理员」提示 | `src/LoginPage.jsx:94-98` |
| 注册用户 | 登录/退出，登录态跨页面保持；`role='user'` | `server/routes/auth.js:93` |
| 管理员 | 继承注册用户能力；切换注册准入开关（`role='admin'`）；首个注册用户自动成为管理员 | `server/routes/auth.js:88-96` |
| 平台机制（非角色） | 登录/注册端点限流（P-02 接口防护）；会话 Cookie 签发与销毁 | `server/lib/rateLimits.js:17-31` |

### 3. 功能范围（G2）

#### 3.1 做什么

| 功能点 | 说明 | 实现锚点 |

| 注册关闭提示 | 已有用户且注册关闭时，登录页显示关闭提示文案，不显示注册入口 | `src/LoginPage.jsx:83-98` |

#### 3.2 不做什么

- 不做邮箱/手机号注册、验证码、找回密码、改密自助服务（改密由管理员在用户治理中代操作，属 D-01）。
- 不做多因素认证、第三方 OAuth 登录。
- 不做注册审批流（注册即时生效，无待审状态）。
- 不做用户清单/禁用/角色管理（属 D-01 权限与用户治理；S-01 仅消费 `disabled`/`role` 字段对登录的影响）。
- 不做注册开关之外的系统配置存储（app_settings 单文档模式属 D-02；S-01 只定义 `registration` 单例的读取语义）。

| 对象 | 说明 | 与其他对象关系 |
|------|------|---------------|

### 5. 业务规则（N3）

#### 5.1 注册开关三参语义（核心规则）

`isRegistrationOpen(userCount, allowRegistration, adminSetting)`（`server/lib/authPolicy.js:11-23`）按优先级判定注册是否开放：

| 优先级 | 条件 | 结果 | 业务含义 |
|--------|------|------|---------|
| 1 | `userCount === 0`（系统无用户） | 恒为开放 | 全新部署绝不能被一份陈旧的「关闭」配置锁死；首个管理员账号不受开关影响 |
| 2 | `adminSetting !== undefined`（管理台已写入） | `Boolean(adminSetting)` | 管理侧持久化值覆盖 env 回落值 |
| 3 | 其他（管理台未设置） | `Boolean(allowRegistration)`（env 回落，默认关闭） | 未设置时与纯 env 行为逐字节兼容 |

补充语义：

- env 解析：`parseAllowRegistration` 仅 `'true'`/`'1'`（大小写不敏感）为真，其余（含未设置）为假（`server/lib/authPolicy.js:6-9`）。
- `/api/auth/status` 与 `/api/auth/register` 共用同一快照函数 `registrationState()`，一次读库同时取用户数与开关，保证「首用户角色判定」与「开关判定」不可能不一致（`server/routes/auth.js:35-54`）。
- 管理台读写接口返回 `source`（'env'｜'admin'）与 `envDefault`，前端可区分当前生效来源（`server/routes/admin.js:45-63`）。

#### 5.2 账号与口令规则

| 规则 | 约束 | 实现锚点 |
|------|------|---------|
| 用户名归一 | 去首尾空白 + 转小写后存储/查重 | `server/lib/password.js:6-8` |
| 用户名格式 | `^[a-z0-9_]{3,32}$`（3–32 位小写字母/数字/下划线） | `server/lib/password.js:3,10-15` |
| 口令长度 | 8–200 字符 | `server/lib/password.js:17-22` |
| 口令存储 | bcrypt 散列，cost=12 | `server/lib/password.js:4,24-26` |
| 用户名唯一 | 归一后查重，冲突返回 409 | `server/routes/auth.js:82-86` |
| 首用户角色 | 注册时系统无用户 → `role='admin'`，否则 `'user'`；新号 `disabled=false` | `server/routes/auth.js:88-96` |

#### 5.3 会话与登录态规则

| 规则 | 约束 | 实现锚点 |
|------|------|---------|
| 会话令牌 | 32 字节随机数的 hex；服务端仅存 SHA-256 散列 | `server/lib/session.js:6-11,30-40` |
| Cookie | 名 `dt_session`（env 可改）；httpOnly；SameSite=lax（env 可设 none/strict）；生产或 SameSite=none 时 secure；TTL 30 天（env 可改） | `server/lib/session.js:3-4,14-28` |
| 登录失败 | 用户不存在与口令错误统一返回 401「Invalid username or password」（不泄露账号是否存在） | `server/routes/auth.js:120-123` |
| 禁用账号 | 登录返回 403「Account is disabled」 | `server/routes/auth.js:124-127` |
| 退出 | 服务端删除会话记录 + 清 Cookie；未登录调用也安全 | `server/routes/auth.js:138-147` |
| 登录后状态刷新 | 前端登录/注册/退出成功后均重拉准入状态，登录页形态即时跟随开关变化 | `src/context/AuthContext.jsx:69-100` |
| 跳转安全 | `?next=` 必须以单个 `/` 开头（拒绝 `//` 与外部地址），防开放重定向 | `src/LoginPage.jsx:12-17` |

#### 5.4 限流规则（依赖 P-02，遵奉者模式）

| 端点 | 默认限额（env 可调） | 说明 |
|------|--------------------|------|
| POST /api/auth/login | 每 IP 20 次 / 15 分钟 | 匿名口令校验是暴力破解目标，bcrypt 之外再加刹车 |
| POST /api/auth/register | 每 IP 10 次 / 60 分钟 | 注册关闭期间仍计数（防滥用面） |
| GET /status、POST /logout、GET /me | 不限 | 保证被限流客户端仍能干净退出 |

依据：`server/routes/auth.js:27-33`；`server/lib/rateLimits.js:17-31`。

### 6. 状态与流转（T2）

本模块无多状态业务单据。涉及的两类简单状态：

1. 账号状态：`disabled` false→true（由 D-01 用户治理修改；本模块仅在登录时消费——禁用即拒登）。规则：不能禁用自己、不能禁用最后一个管理员（在 D-01 侧强制，`server/routes/admin.js:167-176`）。
2. 准入开关状态：`env 默认 → 管理台写入（source: 'env'→'admin'）`；写入后管理值覆盖 env，直至文档被再次修改（无「清除回落 env」操作——本版本未提供）。

### 7. 业务字段（T1）

账号（users 集合）：

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| username | string | 归一后全局唯一，`^[a-z0-9_]{3,32}$` | 登录凭证 |
| passwordHash | string | bcrypt(12) | 不出域，任何响应不返回 |
| role | 'admin' \| 'user' | 首用户必为 admin | 权限判定 |
| disabled | boolean | 默认 false | 禁用即拒登 |
| createdAt | number | epoch-ms | 审计 |

对外用户表示 `publicUser`：仅 `{ id, username, role }`（`server/lib/authPolicy.js:42-51`）——id 是其余模块的 ownerId。

会话（sessions 集合）：`tokenHash`（sha256）、`userId`、`createdAt`、`expiresAt`（`server/lib/session.js:30-40`）。

注册开关（app_settings 单例 `_id='registration'`）：`registrationOpen`（boolean）、`updatedAt`（epoch-ms）、`updatedBy`（管理员用户名）（`server/routes/admin.js:84-88`）。单例字符串 _id 非二十四位 hex，天然唯一且备份往返不变形（`server/lib/authPolicy.js:1-4`）。

### 8. 输入输出规格（T9）

| 接口行为 | 输入 | 输出 / 错误 |
|---------|------|------------|
| 查询注册状态 | — | `{ hasUsers, registrationOpen }` |
| 注册 | `{ username, password }` | 201 + `publicUser` + Set-Cookie；400 格式不符；403 注册关闭；409 用户名占用；429 限流 |
| 登录 | `{ username, password }` | 200 + `publicUser` + Set-Cookie；401 凭证无效；403 账号禁用；429 限流 |
| 退出 | Cookie | 200；清 Cookie |
| 当前用户 | Cookie | 200 + `publicUser`；401 未登录 |
| 管理台读开关 | 管理员 Cookie | `{ registrationOpen, source, envDefault, updatedAt, updatedBy }` |
| 管理台写开关 | `{ registrationOpen: boolean }` | 200 同读结构（source='admin'）；400 非布尔 |

（接口路径与请求细节由 D3 定义，此处为行为规格。）

### 9. 异常与降级（N2）

| 场景 | 行为 |
|------|------|
| 注册关闭时提交注册 | 403「Registration is closed」，注册限额仍计数 |
| 数据库异常 | 5xx + 服务端 message，前端展示错误提示 |
| Cookie 被删/会话过期 | `/me` 401，前端置为未登录态 |
| 限流触发 | 429 + Retry-After（P-02 统一格式），status/logout/me 不受影响可安全退出 |
| 首用户注册时遗留模板迁移失败 | 不阻塞注册本身（迁移为附带动作，`server/routes/auth.js:98-103`） |

### 10. 非功能性要求（N1）

- 用户量级：社团规模（数十至数百账号），单文档读写无性能压力；`registrationState()` 每请求仅一次 `countDocuments` + 一次单例读取（`server/routes/auth.js:40-45`）。
- 口令计算 bcrypt cost=12，登录/注册 QPS 低，可接受。
- 会话 TTL 30 天，滑动场景由前端重新登录覆盖。
- 安全：口令不出域、令牌只存散列、统一 401 不泄露账号存在性、登录页防开放重定向。

### 11. 历史与追溯（N4）

- 账号仅存 `createdAt`；会话无审计日志；开关单例存 `updatedAt`/`updatedBy`（最后一次修改者用户名）。
- 本模块无业务操作日志要求（现有实现未提供）。
