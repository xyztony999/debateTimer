## 第一部分：PRD 正文

### 1. 业务背景与目标（G1）

比赛结束后需要回答「实际用时和计划差多少、哪方超时了几次」。S-04 把计时过程（C-01）沉淀为可复盘的数据资产：比赛中逐阶段自动累计计划 vs 实际用时（正反方分开）与超时次数，随时手动保存快照、控制会话结束自动保存；赛后按历史列表查询、逐阶段明细对比、删除与导出（CSV/JSON）。

核心语义是**快照**：模板名、队名与逐阶段计划值在保存时刻完整复制进记录，赛后修改模板不影响历史记录（BA 附录B「快照」）。

#### 3.2 不做什么

- 不做记录编辑/补录：**只增不改**（append-only，服务端无更新路径，`server/lib/matchLogs.js:34-38` 注释「no update path exists by design」）。
- 不做跨记录统计报表/趋势分析；对比仅限单条记录内的计划 vs 实际。
- 不做记录分享/协作（记录严格归属个人；管理员仅代读治理）。
- 不做附件/照片/语音留存；仅结构化用时数据。
- 不做记录回收站（删除即物理删除，无恢复）。
- 不做服务端 CSV 导出（BD-6 决策：服务器不组装用户来源文本，CSV 在客户端组装）。
- 不做自动周期保存（仅手动按钮 + 会话结束两个触发点）。
- 不做赛后修改队名/模板名回写（快照只读留痕）。

| 对象 | 说明 | 关系 |
|------|------|------|
| 比赛记录（MatchRecord） | 一场比赛的完整快照：模板名、队名、起止时间、逐阶段实绩、服务端汇总 | N:1 账号（ownerId）；引用 S-02 模板**仅存名与内容快照**，无模板 ID 外键，模板删除/改名不影响记录 |

### 5. 业务规则（N3）

#### 5.1 快照语义（核心规则）

| 规则 | 约束 | 实现锚点 |
|------|------|---------|
| 模板按名留痕 | 记录只存 `configName` 字符串（≤100）与队名/阶段数据副本，不存模板 ID；模板后续改名/改配置/删除均不影响既有记录 | `server/lib/matchLogs.js:43`；`src/timer/matchCapture.js:81-94` |
| 队名快照 | aff/neg（各 ≤20，可缺省）随记录留存；明细页缺省回落「正方/反方」文案 | `server/lib/matchLogs.js:54-70`；`src/RecordDetailPage.jsx:126-127` |
| 逐阶段快照 | 每条目固化保存时刻的 label（当前语言显示名）、plannedSeconds、graceSeconds——模板字段变动不追溯 | `src/timer/matchCapture.js:40-59` |
| 只增不改 | 记录无更新接口；复盘发现误差只能删了重采（重新比赛） | `server/lib/matchLogs.js:34-38` |

#### 5.2 采集结算规则

| 规则 | 公式/约束 | 实现锚点 |
|------|----------|---------|
| 实际用时 | `max(0, 计划−剩余) + (宽限−剩余宽限)`：正计时部分 + 已消耗的宽限收尾部分；下限 0 | `src/timer/matchCapture.js:14-17` |
| 双计时 | 正反方按各自 remaining/graceLeft/locked 分别结算；locked 时剩余宽限按 0 计 | `src/timer/matchCapture.js:19-27` |
| 单计时 | 引擎单钟映射到正方，反方恒 0（明细页显示 —） | `src/timer/useDebateTimer.js:160-167`；`src/RecordDetailPage.jsx:199-200` |
| 条目闭合 | 阶段切换/保存时闭合当前条目（写入 actuals + exitedAt），切入新条目；已闭合条目幂等不重复闭合 | `src/timer/matchCapture.js:29-34,40-59` |
| 超时计数 | 超时铃事件仅对「当前未闭合且阶段匹配」的条目对应方 +1 | `src/timer/matchCapture.js:62-75` |
| 空采集不保存 | 无任何条目时 buildMatchPayload 返回 null，保存静默跳过 | `src/timer/matchCapture.js:81-84` |

| 规则 | 约束 | 实现锚点 |
|------|------|---------|
| 手动保存 | 计时页按钮，次数不限；成功后提示（不清空缓冲，可继续比赛再次保存） | `src/TimerControlPage.jsx:359-362`；`src/timer/useDebateTimer.js:393-399` |

| 自动保存失败静默 | 自动路径失败不打扰（不提示），手动路径失败提示 | `src/timer/useDebateTimer.js:400-402` |
| 刷新恢复 | sessionStorage 缓冲的 configKey 与当前模板名一致才恢复；否则清空；大屏跟随页不恢复 | `src/timer/useDebateTimer.js:445-464` |

#### 5.4 服务端校验与限额规则（`server/lib/matchLogs.js:39-135`）

| 字段 | 约束 |
|------|------|
| configName | 字符串 1–100 |
| startedAt/endedAt | epoch-ms 整数；endedAt ≥ startedAt；endedAt ≤ 服务器时间+60s（防未来时间） |

### 6. 状态与流转（T2）

记录为**无状态单据**（append-only，无草稿/生效等生命周期）。过程态在客户端采集缓冲：

```
比赛开始(首个阶段切入) → 缓冲建立，逐阶段开条目/闭合条目
  ├─ 手动保存 → 服务端生成记录（缓冲保留，比赛继续可再存）
  ├─ 会话结束 → 自动保存一次（去重）
  └─ 页面刷新 → 同模板恢复缓冲续采；跨模板清空重开
```

超时计数与条目闭合规则见 §5.2；无服务端状态机。

### 7. 业务字段（T1）

比赛记录（matchLogs 集合）：

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| ownerId | ObjectId | 当前登录用户 | 归属；删除/隔离依据 |
| configName | string | 1–100 | 模板名快照（无模板 ID） |
| teamNames | {aff?, neg?} | 各 ≤20 | 队名快照 |
| startedAt / endedAt | epoch-ms | 见 §5.4 | 比赛起止 |
| savedAt | epoch-ms | 服务端生成 | 列表排序与游标 |
| stages[] | 见 §5.4 | ≤64 条 | 逐阶段快照 |
| summary | {totalPlannedSeconds, totalActualSeconds, overrunCount} | 服务端重算 | 汇总 |
| truncated | boolean? | 仅截断时存在 | 截断标记 |

列表项投影：`{id, configName, teamNames, startedAt, endedAt, savedAt, stageCount, overrunCount, truncated?}`（`server/lib/matchLogs.js:137-149`）；明细项含 stages 全量与 ownerId（`server/lib/matchLogs.js:151-164`）。

### 9. 异常与降级（N2）

| 场景 | 行为 |
|------|------|
| 保存时无采集数据 | 客户端静默跳过（payload=null） |
| 校验失败/超限 | 400 字段级英文 message；阶段超 64 截断入库+truncated 标记（不拒绝）；>64KB 拒绝 |
| 自动保存失败 | 静默（不打扰比赛）；手动失败页面提示 |
| 刷新丢缓冲 | sessionStorage 不可用（隐私模式/配额）仅内存采集，刷新即丢（`matchCapture.js:109-112` try/catch） |
| 明细不存在/越权 | 404 统一「Match record not found」（不区分越权与不存在） |
| 列表失败 | 错误态+重试（`src/RecordsPage.jsx:102-106`） |
| 时钟偏差 | 客户端 endedAt 允许 ≤服务器时间+60s 容差（设备时钟略快不误伤） |

### 10. 非功能性要求（N1）

- 量级：单用户数十至数百条记录，每条 ≤64KB；游标分页默认 20/上限 100。
- 采集为纯函数 + ref，不触发渲染开销；时钟以 wall-clock 锚定（elapsed 实测累加），后台节流不漂移（`src/timer/useDebateTimer.js:252-279`）。
- 导出：CSV 客户端组装零服务端成本；JSON 附件走常规查询。

### 11. 历史与追溯（N4）

- 记录本身即历史资产（快照只增不改）；savedAt/served 端时间可作审计参考。
- 无操作日志（谁在何时保存/删除无独立留痕）；如实记录：现有实现未提供记录级审计。
