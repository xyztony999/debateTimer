## 六、需要主会话转达用户的风险与事实

1. **180 天与《网络安全法》第 21 条。** 本轮按已裁定的 180 天设计。据公开资料，该条要求网络运营者留存相关的网络日志不少于六个月，180 天可能少于六个自然月。该法是否适用于本服务、本审计日志是否属于该条所指的日志，本轮不作判断。如需调整，只改一处常量，但它只影响之后写入的事件。
2. **「完整 IP」成立有前提。** api 域名目前是灰云，仓库里的 Nginx 模板也配置正确，但线上 Nginx 是否与模板一致没有人核实过。写成上线前置条件：api 域名必须保持灰云，或配置 Cloudflare 的 realip。R20 §9.3 给了负责人可以自己执行的确认方法，其中一条是用 curl 带伪造的转发头请求一次，然后看日志里记到的是不是真实来源。
3. **主密钥必须先配、离线保管。** `TOTP_SECRET_KEY` 不配置，两步验证整体停用；配置后丢失，已绑定的账号只能逐个重置。上线检查单的第一项就是它。
4. **线上只有一名管理员。** 上线后该管理员登录，会依次经过隐私确认页和强制绑定，恢复码只显示一次。绑定成功页要求勾选「我已保存」才能继续；万一丢了验证器又没保存恢复码，兜底是服务器脚本 `reset-totp.js`，需要服务器命令行权限。
5. **9 个存量普通账号。** 各自下次访问时才会看到确认页；在那之前，它们的事件不记 IP（符合裁定），也就是说这段时间里这些账号的登录没有 IP 可查。
6. **Google Fonts 仍在向 Google 发送访客 IP。** 隐私说明草稿如实把它列在第三方里。字体非阻塞加载是用户追加的，目前只有官网改了，应用入口页还没改，做法与四项验收写在 P-03 PRD FR-4；本文不为它的效果下结论。
7. **回滚会带来降级。** 回到旧代码后，登录不再校验两步验证，已绑定的账号退回只凭密码登录。R20 §9.5 写了回滚步骤与可选的彻底撤销办法。
8. **发布窗口里的四种新旧组合**都不会产生「未经同意却记了 IP」的数据，行为逐项列在 R20 §9.4。
9. **一个既有情况，提请知悉。** 领域视图数据文件 `profiles/debate-timer/doc-center.json` 的合成器只读取 `profiles/debate-timer/workspace/` 下的一份较早的三文档副本，不读顶层 `workspace/`。本轮在临时目录里模拟过：改动前后的生成结果完全相同，所以不需要因本轮再生成；本轮也没有触碰该文件。但 GUI 的领域视图显示的一直是那份旧副本的内容，与现行的顶层文档不是同一份。
