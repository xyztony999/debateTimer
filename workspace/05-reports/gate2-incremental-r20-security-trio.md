### 2.1 独立核对方法

契约核对不依赖人工阅读：

- **路径核对脚本**解析每个服务文件如何拼出请求地址（字符串常量、辅助函数及其分支），把运行时值统一替换成占位后与后端路由**只做精确匹配**，没有「按尾部匹配」的兜底。脚本自带对照组：故意写错的方法必须判为不匹配，「删除配置」只能匹配到它自己。
- **字段核对脚本**把真实接口进程启动在临时数据库上，实际调用每个接口，把响应递归展开成「字段路径 → 值类型」的集合，与端到端测试所依据的模拟数据比对。期望中有而真实响应没有的字段计为缺失。

## 5. 存量账号在发版后的首次登录（真实数据库）

线上已有账号发版后的第一次登录只能走「旧账号」路径，而新注册的账号不会经过它。为此在全新数据库里按旧版本的写法直接插入两个账号（无任何新字段）和一个发版前就存在的登录会话，再用真实接口进程走完整流程，27 项全部通过：

| 情境 | 实测 |
|------|------|
| 发版前已登录的会话 | 不被销毁；读取当前用户返回待办 `privacy_consent`；其余接口 403 GATE_REQUIRED；隐私说明仍可读取 |
| 存量管理员登录 | 待办依次为 `privacy_consent`、`totp_enroll`；确认前其余接口 403；确认后只剩 `totp_enroll`；绑定成功后待办为空、其余接口恢复 200 |
| 存量普通账号登录 | 只欠 `privacy_consent`；确认后待办为空；两步验证保持自愿 |
| 旧会话在该账号于别处确认之后 | 直接可用 |
| 审计 | 确认前的登录事件 IP 为空；确认后的登录事件带 IP；有 `privacy_consented`、`totp_bound`；没有为旧账号虚构 `registered` 事件 |
| 下一次登录 | 要求输入动态口令；口令通过后完成登录 |
